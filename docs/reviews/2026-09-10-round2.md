# Round 2 review and hardening — 2026-09-10

Review roles: ten read-only automated reviews over storage, feed ingestion,
matching, LLM assessment, container scan, host walk, catalogers, SBOM
writers, CLI/self-update and cross-cutting engineering; three second-round
reviews of the applied fixes; a coordinating agent ran the end-to-end
measurements and the 19 fix jobs (strict per-job file ownership).

## What was measured before fixes

- Host scan (non-root, 5.7M files): the 512 MiB metadata budget was exhausted
  under /docker and /home before the walk reached /usr and /var, so the SBOM
  had **no operating-system component and zero deb packages** while the
  document merely carried `limit-reached=max-total-bytes`. Peak RSS 1.87 GB.
- `advisories.sqlite` was 2.2 GB for 393k records; each `match` re-hashed and
  (without reflink) copied the file. Matching a 52k-component host SBOM took
  56 s at 2.6 GB RSS and wrote a 506 MB JSON because every finding embedded
  its full record.
- Matching accuracy against OSV ground truth was already correct:
  curl 8.14.1-2+deb13u3 → 38 advisories, libexpat1 (upstream expat) → 26.

## Fixed in this round (all with regression tests)

Storage: TOCTOU on meta/legacy index, PAX-inclusive tar expansion cap, 64 KiB
signature cap, recovery of `db.prev` on open, per-affected release filter,
stale reader cleanup, zlib-compressed record JSON (schema bump, updates
tolerate old catalogs), reader isolation `auto|copy|none` with inode/ctime
change detection, details preview on rune boundaries.

Ingestion: zip entry/total caps, per-record field caps without silent version
truncation (feed error instead), sanitized parser errors, `affected[].severity`
preserved, `database_specific` merge with distro-native precedence,
`Debian:sid` normalization, deterministic Alpine ordering, conversion-cache
versioning so 304 responses cannot pin stale conversions.

Matching: OSV `limit` semantics, package-level severity, generated bom-refs
written back into CycloneDX output, host/OS-component conflict handling,
identifier equality for `versions[]`, alias union-find, exit code 2 preserved
over LLM errors, `max_tokens`, compact findings and per-finding streaming JSON
(56 s → 7 s, 506 MB → 78 MB), `--details`.

Scanning: critical OS files read first and exempt from budgets; streaming
cataloger (RSS 1.76 GB → 0.39 GB, metadata-skipped 2,776 → 0, components
37,502 → 52,820); O_NOFOLLOW directory walk with device checks including file
bind mounts; bounded reads; cancellation honoured; `--containers` failures
propagate; image path: referenced-only retention with cumulative
decompression budget, config/manifest digest verification (incl. legacy
`<hex>.json`), digest only when manifest matches applied layers, platform
verification, type-change handling incl. special files, 512-byte sniffing;
catalogers: dpkg hold status, yarn nesting/aliases, TOML strings/escapes,
requirements options, go.mod exclude/unquote/no synthetic stdlib, 16 MiB
scanner buffers, PURL regeneration after merges, purl ':' unencoded.

SBOM: SPDX `comment` key and `OPERATING_SYSTEM` enum, Rocky CPE `resf`, linear
license validator, content-sensitive document identifiers,
`bscan:scan:metadata-skipped`. Official CycloneDX 1.6 / SPDX 2.3 schema
validation of fresh output: 0 errors.

CLI/config/signing: signature record v2 authenticates signer and target (v1
accepted and labelled unauthenticated; `signature_min_version`), pinned
release key ⇒ `.sig` required for self-update, config parser handles BOM,
CRLF, comments, quoted keys/values, nested blocks, strict booleans and
returns errors for unparseable security keys, batch output collisions,
`--help` exits 0, Makefile `release-sign` ordering and license bundling.

## Known limits and follow-ups

- `advisories.sqlite` remains ~1.5 GB (row overhead across 6.2M explicit
  versions from npm MAL records); consider dropping per-version rows for
  records that also carry ranges.
- Matching RSS is dominated by ecosystems that return tens of thousands of
  records per package (Debian `linux`); a streaming Lookup would cut it.
- Many Debian advisories carry no CVSS (UNKNOWN severity); severity
  enrichment from NVD or alias records is not implemented.
- zstd layers and RPM databases are still unsupported.
- Go 1.25.0 is past its support window; pin a supported toolchain for
  releases.
