## Regression fixes

- Publication/modification dates are compared as RFC3339 instants rather than
  lexically, preserving correct ordering across offsets and fractional seconds.
- SQLite readers use isolated copies, with Linux copy-on-write cloning when
  supported, and verify the copied bytes against the verified manifest digest.
  Filesystems without cloning need temporary space for a full database copy.
- New manifests cover retained raw feeds as well as the search catalog.
  Legacy manifests that omitted raw feeds remain readable; their unlisted raw
  files do not gain authentication retroactively.
- Conflicting OS components in CycloneDX and SPDX now produce unknown target
  context for applicability review. An explicit target OS can resolve it.
- Reference URL query strings and fragments are removed before LLM requests.
- Distribution packages with a known source-package version can be matched
  even if the binary package version is absent.
  LLM enrichment uses the package/version actually matched, while the original
  binary subject remains unchanged in the report.
- Records with multiple distinct CVE aliases retain their own advisory IDs.
  This avoids guessing a canonical CVE and merging unrelated descriptions and
  fixed versions. Ordinary single-CVE alias grouping remains supported.
  A CLI recheck against the downloaded catalog kept `GHSA-35jh-r3h4-6jhm`
  (fix 4.17.21) and `GHSA-r5fr-rjxr-66jc` (fix 4.18.0) separate for lodash
  4.17.10; lodash 4.17.21 matched only the latter of these two records.

## Applicability limits

Exact quotation validation detects invented quotations, not incorrect reasoning
about genuine quotations. A model can cite an actual sentence and still infer
the wrong platform applicability. Treat these annotations as human-review aids;
original findings, severity, and failure thresholds remain authoritative.

The API schema is Chat Completions with JSON-object response mode. The live
check establishes compatibility with the tested provider/model only; other
providers may implement a different subset of that protocol.

The follow-up fixed PURL-only affected records: SQLite and legacy indexes derive
missing names from valid matching PURLs, and OSV conversion supports the same
input. Scoped npm, Maven, Debian, Alpine, and ecosystem mismatches have regression
coverage. Existing catalogs require rebuilding their indexes to gain this fix.

The follow-up also added context-aware import, opening, and verification APIs
while retaining existing API wrappers. CLI import, lookup, status, verification,
and matching pass their cancellation context into catalog operations. Reads,
hashing, copy fallback, and SQLite opening/search queries check cancellation.
Legacy index readers also check cancellation while decoding records. External
Store implementations can optionally implement `LookupContext`; otherwise
cancellation is checked before and after their existing `Lookup` call. A kernel
read or clone already in progress is not forcibly interrupted.
Conversion and update propagate cancellation through retained-file copying,
manifest creation, final verification, recovery, and installation checks.

Real CLI SIGINT checks passed: canceling a match while hashing the large catalog
preserved an existing output file; canceling a large archive import preserved
all existing destination file hashes and removed its temporary staging directory.

Release-qualified CLI lookup also filters out records affecting only other
releases; base-ecosystem lookup continues to return all releases.
